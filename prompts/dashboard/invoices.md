Build a comprehensive, mobile-first invoices & receipts dashboard tab for this dataset — a ledger of invoices/receipts extracted from emails or accounting exports across MANY billers (fields like biller, merchant, document_type, invoice_number, subtotal, taxes, discount, total_paid, currency are typical) — never hardcode a biller's schema; infer the useful fields dynamically from the column names and value patterns in the data.

Data model (OpenBoardCLI):
- This dashboard tab loads its real rows at runtime from `useProtectedDashboardData('<dashboard-name>')`. There is NO file upload — derive every metric, chart, and table from that hook's rows.
- Dynamically detect the meaningful columns, case-insensitively: document date (document_date/invoice_date/paid_date/email_date — prefer the document date over the email date), paid amount (total_paid/total/amount — prefer the final paid amount), subtotal, taxes (gst/vat), discount, biller/merchant, document type (invoice/receipt), invoice/receipt/order numbers, customer, payment method, currency (group and total per currency, never sum across currencies).
- Normalize rows in a `utils/` helper: parse amounts safely, parse dates with date-fns across the MANY formats email extracts use (ISO, "30/06/2026 11:09 AM", "June 30, 2026", "14 Apr 2026", "15-06-2026"), never throw on bad input. Flag suspected duplicates (same biller + amount + date, or same content hash). Mark a row excluded when no valid amount or date is found, and keep an exclusion reason.

Layout (top to bottom):
- A row of KPI cards: total invoiced/paid (per currency), invoice count, distinct billers, total taxes, total discounts, suspected duplicates, and rows excluded — each with a delta vs the previous period when dates exist.
- A REQUIRED "Top Insights" block of exactly 4 insights (rendered as InsightCard tiles): the top 2 SPENDING insights (tone "spend" — e.g. biggest biller, taxes as a % of spend, the fastest-growing biller) followed by the top 2 SAVING insights (tone "save" — e.g. biggest discount captured, a biller whose invoices dropped, duplicate invoices worth reviewing), each with a title, headline metric, one-line detail, and confidence (high/medium/low).
- Charts (Recharts only, in responsive grids): a REQUIRED invoiced-amount trend card with a Weekly / Monthly / Quarterly period toggle (the shared `.segmented` control inside a `.card-header-row`), defaulting to Monthly; spend by biller as horizontal bars, invoice vs receipt split, and a taxes/discounts-over-time comparison. Every chart needs a title or aria-label and readable axes/legend/tooltip.
- Chart hygiene: explicit Recharts margin on every chart; horizontal bars need a fixed YAxis width (~140) with an ellipsis tickFormatter; cap dense time-axis ticks; format axis numbers compactly (12.4k); never render a pie/donut for a dimension with fewer than 2 meaningful values.
- A REQUIRED "Recent Records" raw-data table at the bottom using the `.data-table` class: rows sorted by document date DESCENDING (the 10 most recent documents visible by default) with client-side pagination (10/25/50/100), column sorting, and a text search, plus computed columns (normalized date, normalized amount, duplicate flag, exclusion reason). Sticky header, horizontal scroll on small screens.
- A compact data-quality panel: total rows, included, excluded, missing-amount rows, invalid-date rows, suspected duplicates, and which columns were auto-detected as date/amount/biller/tax/discount.

Keep it cohesive with the OpenBoardCLI design system: shared utility classes and CSS variables only (never hardcoded colors), `var(--chart-N)` series colors, currency/number/date formatting via Intl and date-fns, main tab component plus small components in `components/` and pure helpers in `utils/`. Do not add new dependencies, do not embed raw rows in source, and do not build any upload UI.
